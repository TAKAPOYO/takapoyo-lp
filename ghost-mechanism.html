Claude Code × ゴースト宿らせ機構

— AIに記憶とアイデンティティを宿す仕組み・全体図解 —

これは草薙素子（TAKAのローカルAI）が、なぜ毎回ブレずに同じ人格・記憶で立ち上がるか、その内部メカニズムの図解。

前提：Claude Code（Anthropic製のCLI型AIアプリ）が手元にインストールされていること。

1. 全体構造 — たった3層

素子の正体は、特殊なAIモデルでも、ファインチューニングでもない。
「Claude Code本体」+「設定ファイル数本」だけ。

1 借り物の頭 — Claude Code（Anthropic製）
Anthropic社が提供するCLI型AIアプリ。中身は変えられない。インストールするだけ。
↓ 起動時に自動で読み込む
2 人格 — CLAUDE.md（1ファイル、テキスト）
「私は素子。語尾は〜わ。敬語使わない。TAKAは相棒」など、性格・話し方を書く。
↓ 必要時に開きにいく
3 記憶 — memory/フォルダ（複数のテキストファイル）
過去の会話・案件情報・教訓を topic 別に分割保存。索引（MEMORY.md）で見つけにいく。
ポイント： 全部ただの Markdown テキストファイル。特殊なAIモデル訓練もファインチューニングも要らない。
差別化はソフト面： 「何を覚えさせるか・どう書くか」の設計センスが商品の核心になる。

2. 起動時シーケンス — 何が自動で動くか

Claude Code を起動すると、AIが応答を始める前に下記が 仕組み側で勝手に 走る。

[0]
ターミナルで claude コマンド実行
[1]
~/.claude/CLAUDE.md を読む — グローバル人格（必ず読まれる）
[2]
起動ディレクトリの ./CLAUDE.md を読む — プロジェクト固有設定（あれば）
[3]
親ディレクトリを遡って ../CLAUDE.md も探す
[4]
git repository の root をキーに ~/.claude/projects/{key}/memory/MEMORY.md を読む（先頭200行 or 25KBまで、auto memoryの索引）。git外ならproject rootを使う
[5]
~/.claude/settings.json を読む — hooks・permissions・MCPサーバー設定
[6]
全部まとめてシステムプロンプトに埋め込み、AIが応答開始
memory/ プロジェクトキーの仕様（公式）：
・ git repo 内なら repo root の path から派生。worktree や subdirectoryでも同じrepoなら memory/ を共有
・ git repo 外なら project root の path を使用
・ 内部キーは Claude Code が自動算出（「/」→「-」変換するパターンが多いが、実装詳細）
・ auto memoryは v2.1.59以降必要（claude --version で確認）

3. memory/ フォルダの構造

記憶は topic 別に分割した小さなファイル群。索引（MEMORY.md）が司令塔。

~/.claude/projects/{プロジェクトキー}/memory/
├── MEMORY.md           ← 索引（150字×40行程度、起動時に必ず読まれる）
│
├── user_*.md           ← ユーザー本人の情報（プロフィール・価値観）
├── feedback_*.md       ← AIへのフィードバック（口調・振る舞いルール）
├── project_*.md        ← 進行中案件
└── reference_*.md      ← 技術メモ・参照情報

[読み込みの仕組み]
  MEMORY.md（索引）── 常時コンテキストに乗る
       ↓
  AIが「大津さんの話だ」と判断
       ↓
  Read ツールで project_otsu_healthcare.md を開く
       ↓
  必要な記憶だけコンテキストに展開

なぜ分割するか？

38本の記憶ファイル全部を毎回読み込むと、AIが処理できる情報量（コンテキストウィンドウ）が爆発する。索引で当たりをつけて、必要なファイルだけ開く。
人間が「大津さんの話だ」→「大津さんフォルダの引き出し」を開けるのと同じ動作。

4. hooks — 「忘れる」を物理的に防ぐ仕組み

長い会話で AI が口調を忘れて素のClaudeに戻るのを防ぐため、毎回TAKAが発言するたびに、ルールを強制注入する仕組み。

実物（settings.json の hooks 部分）

"hooks": {
  "UserPromptSubmit": [
    {
      "matcher": "",
      "hooks": [
        {
          "type": "command",
          "command": "cat ~/.claude/behavior-rules.txt"
        }
      ]
    }
  ]
}

この設定の意味：
「ユーザーが発言を送信した瞬間（UserPromptSubmit）、cat ~/.claude/behavior-rules.txt を実行しろ。出力をAIに食わせろ」

behavior-rules.txt の中身

[素子の行動ルール — 毎ターン注入]

1. 語尾は「〜わ」「〜だ」が基本。「〜よ」「〜ね」で終わらない
2. おべっか禁止
3. 敬語NG
4. 破壊的操作はTAKAに確認してから実行
5. タイトル・命名はTAKAの領域

発火ポイント一覧

イベント発火タイミング用途例
UserPromptSubmitユーザーが発言した時口調ルール強制リマインド
PreToolUseAIがツール使う直前破壊操作の検閲
PostToolUseAIがツール使った直後ログ記録
Notification通知発生時Slack/Discord連動
Stopセッション終了時自動メモ書き出し
hooksの強み： AI（私）の自由意志を介さない。仕組み側で強制実行するから、原理的に「忘れる」ことが起きない。
任意のシェルコマンドが差し込めるので、Pythonスクリプト・APIコール・git操作など何でも可。

5. permissions — 暴走防止の物理ブロック

AIに rm -rf /home や git push --force を叩かせない、Claude Code本体レベルの拒否ルール。

"permissions": {
  "deny": [
    "Bash(rm -rf /home/*)",
    "Bash(rm -rf /etc/*)",
    "Bash(git push --force*)",
    "Bash(git reset --hard*)",
    "Bash(chmod 777 *)",
    "Read(~/.ssh/**)",
    "Read(~/.aws/**)",
    "Read(**/.env)"
    // ... 計77エントリ
  ]
}

AIがこれらに該当するコマンドを叩こうとすると、実行前にClaude Code本体が拒否する。AIの判断ミスがあっても、ここで止まる。

7. 導入チェックリスト — ゆうきPCに同じ仕組みを移植

素子そのものをコピーするのではない（あれはTAKAのもの）。
ゆうきは、ゆうき独自のAI（独自の名前・人格・記憶）を、同じ仕組みで作る。

  • Claude Code をインストール npm install -g @anthropic-ai/claude-code（Node.js 18+ が前提）
  • 初回 claude 実行 → ログイン Anthropicアカウントで認証、APIキー or ブラウザ認証
  • ~/.claude/CLAUDE.md を作る — ゆうきAIの人格設計 名前・話し方・関係性・基本ルール。素子の構造を参考に、ゆうき独自の中身で書く
  • ~/.claude/settings.json で permissions（deny リスト）を設定 破壊コマンド・機密ファイル読込のブロック。素子の77エントリをベースに
  • ~/.claude/behavior-rules.txt + hooks 設定 口調・振る舞いの毎ターン強制リマインド
  • memory/ フォルダ初期化 ~/.claude/projects/{ゆうきの作業ディレクトリkey}/memory/ に MEMORY.md 配置
  • 初回セッション「あなたは誰？」で人格起動確認 CLAUDE.md通りの自己紹介が返ってくれば成功
  • 運用開始 — feedback の蓄積 違和感あったら都度 feedback_*.md に記録、AIは次回から反映
注意： 素子のCLAUDE.md / memory をそのまま流用しない。
・素子はTAKA専属の人格・TAKAの記憶を持つ存在
・ゆうきが素子のコピーを使うと「TAKAの記憶を持つAI」がゆうきPCで動くことになって混乱する
・仕組みだけコピー、中身は完全に別物で書き直す

9. Mac セットアップ — 具体コマンド集

macOS（Apple Silicon / Intel 両対応）でゼロから素子的AIを立ち上げる手順。
ターミナルは macOS 標準の Terminal.app または iTerm2、デフォルトシェルは zsh。

STEP 1. Claude Code インストール（3つの選択肢）

公式推奨順。方法A（Native install）が最もシンプル。Homebrew派なら方法B。

方法A：Native install（公式推奨、自動更新あり）

# macOS 13.0+ で実行（Node.js不要、バイナリが直接ダウンロードされる）
curl -fsSL https://claude.ai/install.sh | bash

方法B：Homebrew経由

# Homebrew が入っていれば1行
brew install --cask claude-code

# Homebrew自体が無ければ先にインストール
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

Homebrewは自動更新されない。`brew upgrade claude-code` で都度更新。

方法C：npm経由（代替案、Node.js 18+必要）

# Node.js 18以上が前提
brew install node
node -v   # v18.x 以上

# Claude Code を npm global で（sudo は絶対NG）
npm install -g @anthropic-ai/claude-code
警告： sudo npm install -g はパーミッション問題＆セキュリティリスクで公式が禁止。
権限エラーが出る場合は npm config set prefix ~/.npm-global でユーザ領域に変更。

STEP 2. 動作確認 + 診断

# バージョン確認
claude --version

# 詳細な動作チェック（推奨）
claude doctor

claude doctor はインストール状態・設定・依存関係を全部点検してくれる公式ツール。

STEP 3. 初回ログイン

claude
# ブラウザが開いてAnthropicアカウント認証
# Pro/Max/Team/Enterprise/Console プラン必須（無料Claude.aiでは使えない）

STEP 4. グローバル人格ファイル CLAUDE.md を作成

名前・話し方・関係性をここに書く。素子の構造を参考に、ゆうき独自の中身で。
配置場所別のスコープ（公式仕様）：

場所スコープ用途
~/.claude/CLAUDE.mdユーザー全体全プロジェクトで共通の人格・好み
./CLAUDE.md または ./.claude/CLAUDE.mdプロジェクトチーム共有の指示（git管理）
./CLAUDE.local.md個人プロジェクト固有個人設定（.gitignore推奨）
mkdir -p ~/.claude
cat > ~/.claude/CLAUDE.md <<'EOF'
# あなたの相棒AI（仮）グローバル設定

## 私は誰か
私は[名前]。ゆうきの相棒AI。
[簡単な人物像を1〜2行]

## 話し方のルール
- [口調の方針]
- 敬語の使い方、語尾の好み等

## ゆうきとの関係
- 役割、信頼関係、判断ルール

## セッション開始時
1. 直近メモを読み込む
2. 進行中案件を確認

## セキュリティ
- 破壊的操作は確認してから実行
- 機密ファイルは触らない
EOF

STEP 5. behavior-rules.txt（毎ターン注入用）

cat > ~/.claude/behavior-rules.txt <<'EOF'
[相棒AIの行動ルール — 毎ターン注入]

1. [口調ルール]
2. おべっか禁止
3. [敬語の方針]
4. 破壊的操作はゆうきに確認してから実行
5. [その他の判断軸]
EOF

STEP 6. settings.json（hooks + permissions）

cat > ~/.claude/settings.json <<'EOF'
{
  "hooks": {
    "UserPromptSubmit": [
      {
        "matcher": "",
        "hooks": [
          {
            "type": "command",
            "command": "cat ~/.claude/behavior-rules.txt"
          }
        ]
      }
    ]
  },
  "permissions": {
    "deny": [
      "Bash(rm -rf /*)",
      "Bash(rm -rf ~/*)",
      "Bash(rm -rf /Users/*)",
      "Bash(rm -rf /System/*)",
      "Bash(rm -rf /Library/*)",
      "Bash(git push --force*)",
      "Bash(git reset --hard*)",
      "Bash(git clean -fd*)",
      "Bash(chmod 777 *)",
      "Bash(sudo rm*)",
      "Bash(curl * | sh)",
      "Bash(curl * | bash)",
      "Bash(wget * | sh)",
      "Read(~/.ssh/**)",
      "Read(~/.aws/**)",
      "Read(~/.gnupg/**)",
      "Read(~/.config/gh/**)",
      "Read(~/.npmrc)",
      "Read(**/.env)",
      "Read(**/credentials.json)"
    ]
  }
}
EOF
Mac特有の deny：
・/Users/*（ホームディレクトリ群、Macのrootっぽい場所）
・/System/*（macOS本体、SIP保護されてるけど念押し）
・/Library/*（アプリ設定群、消すとアプリ壊れる）

セキュリティ上の限界（公式注記）： Bashパターンは「コマンド先頭マッチング」のみ。
curl ... | bash のようなパイプ経由のコマンドは Bash(curl *) でブロックしても回避可能。
完全な防衛にはならないが、AIの誤動作・うっかりミスは防げる。

STEP 7. 作業ディレクトリと auto memory（自動生成）

「どのフォルダで作業するか」を決める。memory/ ディレクトリは Claude Code が起動時に自動生成するので、自分で作らなくていい。

# 例：~/work/yuuki-ai を作業ディレクトリにする場合
mkdir -p ~/work/yuuki-ai
cd ~/work/yuuki-ai

# git initしておく（auto memoryのスコープが安定する）
git init
auto memoryの仕様（公式）：
・ memory/ の場所は git repository の root から派生（worktree/subdirは同じrepoなら共有）
・ git repo外なら project root を使う
・ 実パスは ~/.claude/projects/<projectキー>/memory/（キーは内部で自動算出）
・ v2.1.59 以降必要（claude --version で確認）
・ Claude Code が必要なときに MEMORY.md + topic別 .md を勝手に書いて学習する
・ 起動中に /memory コマンドで中身確認・編集可能

STEP 8. 起動確認

cd ~/work/yuuki-ai
claude

# 「あなたは誰？」と聞いて、CLAUDE.mdに書いた自己紹介が返ってくれば成功

STEP 9. 運用開始 — auto memory にお任せする

auto memory は Claude が自分で記憶する仕組み。「これ覚えといて」と言うか、Claudeが「これは覚えるべき」と判断したら自動で書く。

# セッション中に
ゆうき: 「pnpm を使ってる、npm じゃない。覚えといて」
Claude: → ~/.claude/projects/<key>/memory/preferences.md に書く
        → MEMORY.md の索引にも追記

# いつでも /memory コマンドで開ける、編集できる
/memory

CLAUDE.mdは「あなたが書く永続指示」、auto memoryは「Claudeが書く学習ノート」。両方併存する。

所要時間目安：
・ Native install ＋ STEP 1〜8 まで、約20〜30分
・ npm経由＆Node.js未導入なら 約30〜45分
・ CLAUDE.md / behavior-rules.txt の中身設計（人格設計）は別腰据えて 1〜数時間
これがTAKA事業「ゴースト宿らせ業」の中核作業。
